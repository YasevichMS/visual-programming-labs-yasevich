## 1. Краткое описание выполненного

В ходе лабораторной работы был освоен Node-RED и создан набор flow, демонстрирующих основные возможности платформы:

- Базовые ноды: `inject` → `function` → `debug`
- Ветвление с помощью `switch`
- Изменение сообщений через `change`
- Формирование данных с помощью `template` (Mustache)
- HTTP-запросы к публичным API (`http request`)
- Работа с MQTT (публикация и подписка через публичный брокер)
- Создание собственных HTTP API (три GET-эндпоинта с обработкой ошибок 400/404)
- Dashboard: `ui_gauge` и `ui_chart` для визуализации данных датчика
- Telegram-бот с командами `/start`, `/info` и echo-режимом
- Запись и чтение файлов (`file out` / `file in`)
- Работа с `flow context` (счётчик, сохраняющий значение между сообщениями)

Все flow были протестированы, для API-эндпоинтов подготовлена документация.

## 2. Примеры AI-промптов

При выполнении работы использовались запросы к AI для генерации кода и flow. Примеры ключевых промптов:

1. **Базовый function-нод**  
   «Собрать flow inject → function → debug. В коде function использовать let/const, if/else, цикл for, массив, объект. Функция возвращает объект с полем payload.»

2. **Switch**  
   «Собрать flow inject → function → switch → debug (выход 1) / debug (выход 2). В switch настроить правило ветвления по msg.payload.»

3. **HTTP API**  
   «Создать 3 GET-эндпоинта в Node-RED: /api/text, /api/info, /api/items/:id. Для третьего при некоторых значениях параметров возвращать 400 или 404.»

4. **Dashboard**  
   «Установить node-red-dashboard. Gauge для числового показателя. Chart для истории значений. Inject, имитирующий датчик температуры.»

5. **Telegram-бот**  
   «Создать бота через BotFather. Имя: tvl_lab2_Yasevich_bot. Команды: /start + одна команда на выбор. Echo-ответ на произвольное сообщение.»

6. **Контекст**  
   «Продемонстрировать работу с flow context: сделать счётчик, который живёт между сообщениями.»

## 5. Выводы

Лабораторная работа позволила на практике познакомиться с Node-RED как инструментом low-code / visual programming для автоматизации и интеграции.

Основные выводы:

- Node-RED удобен для быстрого прототипирования: от простых преобразований данных до полноценных HTTP API и Telegram-ботов.
- Большинство типовых задач (работа с файлами, MQTT, HTTP, дашборды) решаются стандартными или легко устанавливаемыми нодами.
- Function-нод даёт возможность писать обычный JavaScript, когда визуальных блоков недостаточно.
- Контекст (`flow` / `global`) позволяет хранить состояние между сообщениями без внешних баз данных.
- При работе с файлами и внешними сервисами важно учитывать права доступа и корректные пути.
- AI существенно ускоряет написание кода function-нод и генерацию готовых flow, но результат всегда нужно проверять и дорабатывать вручную.

В целом Node-RED показал себя как мощный и гибкий инструмент, подходящий как для учебных задач, так и для реальных сценариев автоматизации.
